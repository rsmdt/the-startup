# Product Requirements Document

> [!NOTE]
> This PRD answers **WHY** and **WHAT** — the problem, who has it, and what "done" looks like.
> It carries no technical design (that is `solution.mdx`) and no implementation steps.
> Unresolved decisions live in one place: the **Open Questions** table at the foot of the document.
> **Stable IDs:** features `FR-N`, criteria `AC-N.M`, plus `NFR-N`, `EV-N`, `DR-N` — permanent once
> assigned; `plan.mdx` traces them, so renumbering breaks traceability.

<details>
<summary>📋 Validation Checklist — the single checklist in this document; run before declaring complete</summary>

### Gates (must pass)

- [ ] All required sections complete; no [NEEDS CLARIFICATION] markers remain
- [ ] Problem statement is specific, measurable, and validated by evidence — not assumptions
- [ ] Every feature has testable acceptance criteria (Gherkin); all IDs unique and never renumbered
- [ ] Every NFR has a measurable fit criterion; every EV gate states observable behavior + threshold (WHAT, never HOW)
- [ ] No contradictions between sections; no technical implementation details or API specifications

### Quality (should pass)

- [ ] Context → Problem → Solution flow makes sense; a new team member could understand this PRD
- [ ] All MoSCoW categories addressed; every metric has corresponding tracking events
- [ ] Every data item carries purpose, retention, and classification; user rights addressed
- [ ] Every dependency carries owner, need-by, and impact-if-late
- [ ] Jargon defined in the Glossary; acronyms expanded on first use

### MECE (each enumeration: no overlap, no gaps)

- [ ] **Stakeholders** — one concern per row; everyone affected is represented, including support, ops, compliance, and the negatively affected
- [ ] **Personas** — distinct goals and pain points; all user types who interact are present
- [ ] **Journeys** — each a distinct path; primary, secondary, and error/recovery mapped; every persona has at least one journey
- [ ] **Features** — no capability stated twice, even across MoSCoW categories; every persona's problem fully covered; Won't-Have names the confusable capabilities
- [ ] **Acceptance criteria** — each tests a unique condition; happy, error, and edge paths covered
- [ ] **NFRs** — one requirement per quality concern; every relevant dimension specified or rejected with a one-line reason
- [ ] **Evaluation criteria** — no two gates pass or fail together by construction; every release-blocking behavior is gated
- [ ] **Data** — each item listed once with a single purpose; nothing held that isn't listed
