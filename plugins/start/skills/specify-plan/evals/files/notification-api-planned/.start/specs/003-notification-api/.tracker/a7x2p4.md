## Features
- AC-1.1 — Given a valid recipient and message, When a service submits a notification, Then it receives a notification ID and the notification is queued
- AC-1.2 — Given a request with no recipient, When a service submits it, Then it is rejected with a validation error naming the missing field

## Behavior — EARS
- WHEN a valid notification is submitted, THE SYSTEM SHALL store it with status `queued` and respond `202` with its ID
- IF the request has no recipient, THEN THE SYSTEM SHALL respond `400` naming the `recipient` field

## Quality Gates
- NFR-1 — p95 submit latency < 200 ms at 100 req/s
- NFR-2 — 0 lost notifications across a worker restart during delivery
