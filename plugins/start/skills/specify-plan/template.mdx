# Implementation Plan: {{FEATURE_TITLE}}

> [!NOTE]
> This plan is the **executable sequence** `/implement` runs. It is an ordered set of
> **BEANs** (Bundled EARS + Acceptance Nodes) — self-contained vertical slices. Each BEAN
> correlates the deliverable **features** (acceptance criteria from requirements), the
> **behavior** the solution must exhibit (EARS), the **quality gates**, and the holdout
> **acceptance scenarios** that prove it. `/implement` builds each BEAN through a barriered

> *what the slice delivers and how it is proven* — never the steps to build it; the loop's
> code agent owns HOW.

## BEANs

Each BEAN is a **vertical slice**: one coherent, user-observable deliverable carried
end-to-end, atomic enough for a single code agent to build. A later BEAN may depend on an
earlier one and extend its foundation. `/implement` topologically sorts BEANs by their
declared dependencies and runs independent BEANs concurrently — so order them by dependency,
not by layer, and keep `Depends on:` accurate. It is the whole parallelization contract.
